# 扩展与调度

AI 工作负载同时受 GPU 显存、算力、上下文长度和输出长度影响，单纯按请求数扩缩容常会误判。

## 容量模型

区分 prefill 密集与 decode 密集请求；按模型、上下文桶和服务等级分队列。长请求应避免阻塞交互式短请求。

## 弹性策略

- 结合队列等待时间、运行中 token 和 KV Cache 使用率扩容。
- 预热权重与 kernel，避免冷启动直接接流量。
- 过载时限流、降级模型、缩短最大输出或异步排队。
- 多租户设置 token 配额与公平调度权重。

## 高可用

模型调用通常可重试，但流式输出后重试会产生重复内容。网关需保存生成偏移或向客户端暴露可恢复的 run id。
